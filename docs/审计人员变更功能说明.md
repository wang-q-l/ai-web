# 审计人员变更 - 文书移交功能

## 功能概述

审计人员变更功能用于处理审计人员离职或调岗时的文书移交工作。当审计人员需要变更时，系统会将其创建的所有文书移交给其他审计组的人员，确保审计工作的连续性。

## 功能特点

### 1. 步骤式交互设计

参考飞书、钉钉等应用的离职交接流程，采用 4 步骤式交互：

- **步骤 1**：选择变更人员
- **步骤 2**：选择移交文书
- **步骤 3**：选择接收人员
- **步骤 4**：确认移交

### 2. 智能筛选

- 支持按姓名、工号、审计组筛选人员
- 自动过滤无文书的人员（步骤 1）
- 自动排除变更人员自己（步骤 3）

### 3. 批量操作

- 支持批量选择文书进行移交
- 显示已选择文书数量
- 支持全选/取消全选

### 4. 移交确认

- 显示完整的移交信息摘要
- 支持填写移交原因（选填）
- 二次确认避免误操作

### 5. 移交记录

- 记录所有移交历史
- 显示移交人、接收人、文书数量、移交时间等信息
- 支持查看移交原因

## 页面结构

### 步骤条

- 使用 Element Plus 的 Steps 组件
- 显示当前进度
- 已完成步骤显示成功状态

### 步骤 1：选择变更人员

- 筛选表单：姓名、工号、审计组
- 人员列表表格：
  - 显示姓名、工号、部门、审计组
  - 显示待移交文书数量（标签形式）
  - 只有有文书的人员才能选择
- 点击"选择"按钮进入下一步

### 步骤 2：选择移交文书

- 显示变更人员信息
- 文书列表表格（支持多选）：
  - 文书名称、类型、创建时间、状态
  - 状态使用不同颜色的标签区分
- 底部显示已选择文书数量
- 必须至少选择一份文书才能进入下一步

### 步骤 3：选择接收人员

- 筛选表单：姓名、审计组
- 接收人员列表表格：
  - 显示姓名、工号、部门、审计组
  - 自动排除变更人员自己
  - 建议选择同一审计组的人员
- 点击"选择"按钮进入下一步

### 步骤 4：确认移交

- 移交信息摘要：
  - 变更人员信息
  - 接收人员信息
  - 移交文书列表
  - 移交文书数量
- 移交原因输入框（选填）
- 确认按钮执行移交

### 移交记录

- 显示所有历史移交记录
- 表格列：
  - 变更人员（姓名 + 工号）
  - 接收人员（姓名 + 工号）
  - 移交文书数量
  - 移交原因
  - 移交时间
  - 操作人

## 交互流程

```
开始
  ↓
选择变更人员（必须有待移交文书）
  ↓
选择移交文书（至少选择一份）
  ↓
选择接收人员（不能是变更人员自己）
  ↓
确认移交信息
  ↓
执行移交
  ↓
显示成功提示
  ↓
查看移交记录
```

## 样式规范

### 卡片样式

- 步骤条卡片：固定高度，不压缩
- 内容卡片：占据剩余空间，使用 flex: 1

### 步骤内容

- 步骤标题：h3 标签，字体大小 18px，加粗
- 步骤描述：灰色文字，字体大小 14px
- 重要信息：使用 strong 标签加粗

### 表格

- 使用 Element Plus 的 Table 组件
- 无边框样式
- 固定表头，数据可滚动

### 按钮

- 上一步：默认样式
- 下一步：主要按钮（type="primary"）
- 确认移交：成功按钮（type="success"）
- 取消：默认样式

### 信息摘要

- 使用卡片布局
- 浅色背景（#f5f7fa）
- 圆角 8px
- 内边距 20px

## 数据流

### Mock 数据

- 人员列表：5 个审计人员，分属 3 个审计组
- 文书数据：按人员 ID 分组存储
- 移交记录：记录所有移交历史

### API 接口

- `getPersonnelList`：获取人员列表
- `getPersonnelDocuments`：获取人员文书列表
- `transferDocuments`：执行文书移交
- `getTransferRecords`：获取移交记录列表

### 状态管理

- 当前步骤：currentStep（0-3）
- 选中的变更人员：selectedFromPerson
- 选中的文书：selectedDocuments
- 选中的接收人员：selectedToPerson
- 移交原因：transferReason

## 注意事项

1. **数据验证**
   - 步骤 1：必须选择有文书的人员
   - 步骤 2：必须至少选择一份文书
   - 步骤 3：不能选择变更人员自己

2. **用户体验**
   - 每步操作都有明确的提示
   - 使用加载状态避免重复提交
   - 操作成功后显示成功提示
   - 支持上一步返回修改

3. **数据一致性**
   - 移交后更新人员文书数量
   - 移交后更新文书归属
   - 记录移交历史便于追溯

4. **权限控制**
   - 建议只有管理员才能执行人员变更
   - 可以在路由守卫中添加权限检查
