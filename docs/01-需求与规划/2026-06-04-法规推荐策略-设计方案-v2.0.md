# 法规推荐策略 设计方案

## 一、项目概述

### 1.1 背景

「法规推荐策略」面向审计业务场景，提供"问题描述 → 法规依据"的智能推荐能力。审计人员撰写问题表述、定性依据时，系统根据问题内容自动从法规库中匹配最适用的条款，作为辅助决策依据。

### 1.2 设计原则

本方案围绕 **极简、易理解、可调优** 三个原则：

- **少即是多**：只保留真正影响推荐质量的核心参数，避免过度配置
- **AI 兜底**：复杂的语义理解交给大模型，前端不维护同义词、不分场景、不分层级
- **业务可控**：保留 3 个核心权重让业务侧根据实际效果微调

### 1.3 核心价值

| 角色 | 收益                                                  |
| ---- | ----------------------------------------------------- |
| 业务 | 一个页面就能看完所有可调参数；试推荐立即可见效果      |
| 开发 | 推荐流程逻辑简单清晰，少量参数即可实现核心功能        |
| 产品 | 易讲解、易演示，3 个维度配合 1 个阈值即可向客户说清楚 |

## 二、功能范围

### 2.1 页面构成

```
法规推荐策略页
├─ 全局策略表单
│  ├─ 打分权重（3 个滑块）
│  │  · 关键词匹配
│  │  · 问题案例匹配
│  │  · 颁布年份新旧
│  ├─ 最低推荐阈值
│  └─ Top N
└─ 推荐试验台抽屉（顶部按钮触发，可即调即验）
```

### 2.2 业务使用入口（法规推荐页）

```
法规推荐页（沿用既有设计）
├─ 问题新增抽屉
└─ AI 助理思考过程展示
```

### 2.3 不再包含的能力

为简化方案与降低维护成本，明确不再做以下能力：

- ❌ 场景覆盖策略（取消 Tab2）
- ❌ 同义词表维护（取消 Tab3，由大模型自动语义识别）
- ❌ 法规层级基准分（取消 Tab4，不区分法规层级）
- ❌ 过滤条件（不区分法规层级、不区分业务标签，默认全部法规参与匹配）
- ❌ 业务标签匹配维度（取消该打分维度）
- ❌ 历史采纳率维度（取消该打分维度）

## 三、推荐流程

### 3.1 流程总览

整套推荐流程分 4 步，从用户输入到 Top N 输出：

```
[用户输入：problem]
        ↓
① 关键词智能识别（LLM 自动提取）
        ↓
② 候选召回（全部法规参与）
        ↓
③ 三维度打分
   · 关键词匹配  × 0.40
   · 问题案例匹配 × 0.40
   · 颁布年份新旧 × 0.20
        ↓
④ 输出控制（阈值过滤 + Top N）
        ↓
[Top N 推荐结果]
```

### 3.2 阶段 ① 关键词智能识别（由 LLM 完成）

由大模型直接理解用户问题，无需前端维护同义词表。

**输入**：用户的问题描述（自然语言）

**LLM 任务**：

- 抽取用户问题中的核心业务概念
- 自动展开同义词、近义词、上下位词
- 识别审计领域术语（如"院中院"、"三公经费"等）

**输出**：扩展后的关键词集合

**示例**：

```
输入：开发区医院将健康管理中心等5个科室与社会资本合作设立营利性项目

LLM 输出：
关键词：公立医院、医疗机构、科室、合作、营利性、社会资本
扩展词：院中院、变相承包、合资经营
```

调用模型建议使用便宜的小模型（如 Haiku），单次调用控制在 1 秒内。

### 3.3 阶段 ② 候选召回

法规库中所有法规均参与本阶段，**不做任何硬过滤**。

```ts
for (const clause of clauses) {
  const keywordHit = clause.keywords.some((kw) =>
    expandedTokens.some((t) => kw.includes(t) || t.includes(kw))
  )

  if (keywordHit) {
    candidates.push(clause)
  }
}

// 截断保护：候选超过 200 条时只保留前 200
if (candidates.length > 200) {
  candidates = candidates.slice(0, 200)
}
```

只要某条法规与扩展关键词集合有任何子串匹配，即进入候选。

### 3.4 阶段 ③ 三维度打分

每个维度先归一化到 0~1，再乘以权重。综合得分 = 三个维度贡献分之和（范围 0~1）。

#### 维度 1 · 关键词匹配（默认权重 0.40）

**计算公式**：

```ts
const hits = clause.keywords.filter((kw) =>
  expandedTokens.some((t) => kw.includes(t) || t.includes(kw))
).length

const keywordMatchRaw = Math.min(1, hits / Math.max(1, Math.min(clause.keywords.length, 4)))
```

**说明**：

- 数清楚法规关键词被命中了多少个
- 命中数除以"法规关键词总数与 4 取较小值"
- 命中 4 个就到顶，不让长关键词列表的法规吃亏

**示例**：

| 法规关键词 | 命中数 | 分母 | 原始分 |
| --- | --- | --- | --- |
| `['公立医院','院中院','合作','营利性','科室','社会资本']`（6 个） | 4 | min(6,4)=4 | 4/4=**1.00** |
| `['采购','招标','公开招标','违规']`（4 个） | 0 | min(4,4)=4 | 0/4=**0.00** |
| `['挪用','私分']`（2 个） | 2 | min(2,4)=2 | 2/2=**1.00** |

#### 维度 2 · 问题案例匹配（默认权重 0.40）

**业务含义**：根据"用户当前问题"和"历史问题案例库"做语义相似匹配，把"历史相似案例引用过的法规"分数抬高。这是**协同推荐**的思路。

**两步关联**：

```
[用户当前问题]
       ↓
       ↓ 步骤 A：LLM 语义相似度匹配
       ↓
[历史相似案例 Top 5]
       ↓
       ↓ 步骤 B：取这些案例引用过的法规集合
       ↓
[相关法规 + 命中权重]
```

**计算公式**：

```ts
// 步骤 A：找历史相似案例（取 Top 5，相似度 ≥ 0.6）
const similarCases = await llmFindSimilarCases(query, historyCases, {
  topN: 5,
  minSimilarity: 0.6
})
// similarCases = [{ caseId, similarity, citedClauseIds }, ...]

// 步骤 B：构建"法规命中权重表"
const caseHitWeight = new Map<string, number>()
for (const cs of similarCases) {
  for (const clauseId of cs.citedClauseIds) {
    // 该法规的命中权重 = 各历史案例相似度之和
    const prev = caseHitWeight.get(clauseId) ?? 0
    caseHitWeight.set(clauseId, prev + cs.similarity)
  }
}

// 步骤 C：当前候选法规的"问题案例匹配"原始分
const maxWeight = Math.max(...caseHitWeight.values(), 1) // 归一化基准
const caseMatchRaw = (caseHitWeight.get(clause.id) ?? 0) / maxWeight
```

**说明**：

- 没有历史案例引用过的法规，原始分 = 0
- 多个相似案例都引用过的法规，分数会累加（更可信）
- 用本批 Top 法规中的最大权重做归一化，保证分布在 0~1

**示例**：

```
用户问题："开发区医院科室外包给民营机构"

LLM 找到相似案例：
  案例 #1（相似度 0.85）：「某市医院出租科室给私营公司」
    → 引用 [《医卫法》40条, 《医疗机构分类管理意见》3条]
  案例 #2（相似度 0.72）：「公立医院与社会资本合作设立营利性项目」
    → 引用 [《医卫法》40条]
  案例 #3（相似度 0.68）：「医院承包科室违规」
    → 引用 [《医疗机构分类管理意见》3条]

caseHitWeight 计算：
  《医卫法》40条 = 0.85 + 0.72 = 1.57
  《医疗机构分类管理意见》3条 = 0.85 + 0.68 = 1.53

归一化（maxWeight=1.57）：
  《医卫法》40条 → 1.57/1.57 = 1.00
  《医疗机构分类管理意见》3条 → 1.53/1.57 ≈ 0.97
  其他候选法规（无历史关联）→ 0
```

**冷启动策略**：

```
若历史案例库为空 → 该维度全员归零
若历史案例 < 50 条 → 权重自动降为原始 50%（避免过早拟合）
```

#### 维度 3 · 颁布年份新旧（默认权重 0.20）

**计算公式**：

```ts
const currentYear = new Date().getFullYear()
const recencyRaw = Math.max(0, Math.min(1, (clause.year - 1990) / (currentYear - 1990)))
```

**说明**：

- 1990 年作为下限，越接近今年得分越高
- 1990 年之前的归 0
- 该维度仅作辅助，权重最小

**示例（当前年份 2026）**：

| 颁布年份 | 计算  | recencyRaw |
| -------- | ----- | ---------- |
| 2026     | 36/36 | **1.00**   |
| 2020     | 30/36 | **0.83**   |
| 2014     | 24/36 | **0.67**   |
| 2000     | 10/36 | **0.28**   |
| 1990     | 0/36  | **0.00**   |
| 1985     | 截断  | **0.00**   |

#### 综合得分公式

```ts
const w = strategy.weights // 三项之和已归一化为 1

const scoreBreakdown = {
  keywordMatch: keywordMatchRaw * w.keywordMatch,
  caseMatch: caseMatchRaw * w.caseMatch,
  recency: recencyRaw * w.recency
}

const score = Object.values(scoreBreakdown).reduce((sum, v) => sum + v, 0)
// 综合得分范围：0~1
```

#### 完整端到端示例

**输入**：

- query = "公立医院将科室与社会资本合作设立营利性项目"
- 候选《基本医疗卫生与健康促进法》第 40 条第三款
  - year = 2020
  - keywords = `['公立医院','院中院','合作','营利性','科室','社会资本']`

**生效权重（默认 0.40 / 0.40 / 0.20）**

**计算过程**：

| 维度         | 原始分                     | × 权重 | 贡献分    |
| ------------ | -------------------------- | ------ | --------- |
| 关键词匹配   | 1.00（命中 4 个达上限）    | × 0.40 | **0.400** |
| 问题案例匹配 | 1.00（历史最相似案例引用） | × 0.40 | **0.400** |
| 颁布年份     | 0.83（2020 年）            | × 0.20 | **0.166** |
| **综合得分** |                            |        | **0.966** |

### 3.5 阶段 ④ 输出控制

#### 阈值过滤

```ts
let filtered = scored.filter((s) => s.score >= strategy.threshold)

// 兜底：阈值卡死全部时
if (filtered.length === 0 && scored.length > 0) {
  filtered = scored.filter((s) => s.score >= strategy.threshold / 2).slice(0, 3)
  meta.lowConfidence = true // 标记低相关度
}
```

#### 排序与截断

```ts
filtered.sort((a, b) => b.score - a.score)
results = filtered.slice(0, strategy.topN)
```

## 四、页面交互设计

### 4.1 页面结构

```
┌──────────────────────────────────────────────┐
│ 法规推荐策略   [推荐试验台]                  │
│  配置审计问题推荐法规依据时使用的打分权重    │
│  与最低推荐阈值                              │
├──────────────────────────────────────────────┤
│ 打分权重                                     │
│  关键词匹配     ━━━━━○━━━ 0.40  占 40%     │
│  问题案例匹配   ━━━━━○━━━ 0.40  占 40%     │
│  颁布年份新旧   ━━○━━━━━━ 0.20  占 20%     │
│                                              │
│ 输出控制                                     │
│  最低推荐阈值   ━━━━━○━━━ 0.50              │
│  Top N          [-]  5  [+]                  │
│                                              │
│  [保存全局策略]  [重置默认]                  │
└──────────────────────────────────────────────┘
```

### 4.2 字段说明

#### 打分权重区

| 字段         | 范围     | 默认值 | 说明                             |
| ------------ | -------- | ------ | -------------------------------- |
| 关键词匹配   | 0~1 滑块 | 0.40   | 用户问题与法规关键词命中的相关度 |
| 问题案例匹配 | 0~1 滑块 | 0.40   | 与历史问题案例的语义相似度       |
| 颁布年份新旧 | 0~1 滑块 | 0.20   | 法规颁布越新得分越高             |

每个滑块右侧显示两行：

- 当前原始值（如 `0.40`）
- 归一化后占比（如 `占 40%`）

提交保存时三项权重按比例归一化，总和强制等于 1。

#### 输出控制区

| 字段         | 范围          | 默认值 | 说明                         |
| ------------ | ------------- | ------ | ---------------------------- |
| 最低推荐阈值 | 0~1 滑块      | 0.50   | 综合得分低于此值的法规被剔除 |
| Top N        | 1~20 数字输入 | 5      | 推荐结果最多展示几条         |

### 4.3 推荐试验台

顶部「推荐试验台」按钮，点击弹抽屉：

- 输入问题描述（textarea，500 字限制）
- 一键试推荐 → 立刻看到 Top N 结果
- 每条结果展示：法规名 / 条款号 / 原文 / 综合得分 / 三维度评分明细
- 使用当前未保存的策略参数，便于即调即验

## 五、数据结构

### 5.1 策略配置

```ts
interface StrategyConfig {
  weights: {
    keywordMatch: number // 关键词匹配权重，默认 0.40
    caseMatch: number // 问题案例匹配权重，默认 0.40
    recency: number // 颁布年份权重，默认 0.20
  }
  threshold: number // 最低推荐阈值，默认 0.50
  topN: number // 推荐结果数，默认 5
}
```

### 5.2 法规条款

```ts
interface Clause {
  id: string
  regulationName: string
  articleNo: string
  articleText: string
  year: number
  keywords: string[] // 由 LLM 离线提取（不再依赖前端同义词扩展）
}
```

### 5.3 历史问题案例

```ts
interface ProblemCase {
  id: string
  problemDescription: string // 历史问题描述
  citedClauseIds: string[] // 该案例引用过的法规 ID 列表
  createdAt: string
}
```

历史案例由业务沉淀产生（用户每次推荐结果被采纳后自动记录），无需前端维护。

## 六、边界情况处理

| 场景                  | 处理方式                                              |
| --------------------- | ----------------------------------------------------- |
| 用户问题为空          | 直接返回 `{ code: 400, message: '问题描述不能为空' }` |
| LLM 关键词识别失败    | 降级用基础分词（标点切分），继续执行后续阶段          |
| 历史案例库为空        | 问题案例匹配维度全员 0；其他维度照常打分              |
| 历史案例数 < 50       | 问题案例匹配权重自动降为 50%，避免过早拟合            |
| 候选超过 200 条       | 截断到前 200 条，防御性保护                           |
| 全部条款 score < 阈值 | 兜底放宽到阈值/2 取 Top 3，标记低相关度               |
| 三个权重总和不为 1    | 保存前自动归一化，写回 UI 让用户看到生效值            |

## 七、AI 助理思考过程展示

业务使用入口的 AI 助理在用户点击「法规推荐」后，按推荐流程展示思考卡片：

| 卡片              | 对应阶段 | 展示内容                         |
| ----------------- | -------- | -------------------------------- |
| #1 关键词智能识别 | ①        | 扩展后的关键词 chips（逐个跳出） |
| #2 候选召回       | ②        | 候选法规数量滚动                 |
| #3 三维度打分     | ③        | 3 个维度进度条逐条增长           |
| #4 输出筛选       | ④        | 阈值过滤 + Top N 截断            |

每张卡片：

- 上一卡片跑完，下一卡片才淡入并开始跑（不并发）
- 完成后显示对勾 + 关键产物
- 全部跑完展示推荐卡片列表
